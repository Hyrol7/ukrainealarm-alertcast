# Зміни

## 1.0.0

Перший випуск.

- Стан регіонів з ієрархією (громада → район → область): `active`, `partial`, `none`; рівні
  `red` (ракетна небезпека), `yellow` (загроза БпЛА), `unknown`; окремо для кожного типу тривоги.
- API v1: `/status`, `/stream` (SSE: знімок, зміни, свіжість даних), `/regions` (ETag), `/me`.
- Сумісність з ukrainealarm API v3: `/api/v3/alerts`, `/alerts/{id}`, `/alerts/status`, `/regions`.
- Сторінка документації API `/docs` (як Swagger): усі запити, схеми, помилки, приклади (curl, JS,
  Python, ESP8266) і «Виконати» з власним токеном.
- Токени: хеш у БД, ліміти запитів і потоків, термін дії, регіони, адреси, дозвіл на `?token=`;
  керування через локальний сокет (`alertcast token …`) або адмінку, зміни діють миттєво.
- Адмінка (`ADMIN_LISTEN`, лише loopback → VPN-сайт): пароль + 2FA (TOTP, без повтору кодів),
  токени з QR, моніторинг з графіками за 24 год (затримки, потоки, запити), тестова область,
  журнал подій. `alertcast admin setup|status|logout`.
- Тестова область: вигадані регіони з ручним керуванням тривогами для перевірки пристроїв.
- Головна сторінка — таблиця поточних тривог, оновлюється сама.
- Захист: однакова 401, блокування підбору, ліміти на адресу й загалом, перевірка мереж
  Cloudflare для `CF-Connecting-IP`, окремий вхід для VPN.
- Зв'язок з alertd: відновлення після обриву, повний resync при зміні бази alertd, позначка
  `stale`, коли дані давно не підтверджувались.
- Сесії браузера: `POST /api/v1/session` → cookie `__Host-ac_session` (HttpOnly, Secure, SameSite=Strict).
- `alertcast verify` — звірка з живим ukrainealarm одним запитом.
- Сторожовий таймер systemd: зависла служба перезапускається.
- systemd: заборона вихідних з'єднань (лише localhost), фільтр системних викликів,
  `MemoryDenyWriteExecute`; `systemd-analyze security` 0.9.
