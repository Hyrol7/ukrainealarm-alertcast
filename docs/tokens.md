# Токени

Кожен пристрій чи застосунок отримує власний токен — так його можна обмежити або відкликати,
не чіпаючи інших. Керування — лише на сервері через `sudo` (служба приймає команди тільки від
root через локальний сокет `/run/alertcast/admin.sock`). Зміни діють миттєво.

```bash
sudo alertcast token add --name "Лампа батьків" --regions 32 --rpm 30 --streams 1
```

```
ID:          0d5d4366
Назва:       Лампа батьків
…
Токен (показується лише зараз, збережіть його):

  ac_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX   (приклад)
```

Сам токен у БД не зберігається — лише його SHA-256. Загубили — зробіть `rotate`.

## Команди

| Команда | Що |
|---|---|
| `alertcast token add --name "…" [параметри]` | створити |
| `alertcast token list` | усі токени: ліміти, регіони, адреси, кількість запитів і відмов, остання активність |
| `alertcast token show ID` | подробиці одного |
| `alertcast token edit ID [параметри]` | змінити лише вказані параметри |
| `alertcast token rotate ID` | новий секрет, ті самі налаштування (старий одразу перестає працювати) |
| `alertcast token revoke ID` | відкликати назавжди |

Після `edit`, `rotate` і `revoke` відкриті потоки цього токена закриваються з подією `bye`, а
браузерні сесії гаснуть; пристрій перепідключиться вже за новими правилами.

## Параметри

| Параметр | Типово | Що |
|---|---|---|
| `--name "…"` | — | назва для себе (обов'язково при створенні) |
| `--regions 4,32` | усі | дозволені регіони; дозвіл на область відкриває всі її райони й громади, але не навпаки. `""` — усі |
| `--rpm 60` | `DEFAULT_RPM` | запитів на хвилину (з невеликим запасом на сплеск) |
| `--streams 2` | `DEFAULT_STREAMS` | одночасних потоків `/api/v1/stream`; `0` — лише запити стану |
| `--expires 2027-06-01` | безстроково | діє до кінця цього дня; або `90d`, `12h`; `never` — без терміну |
| `--ip 10.77.0.0/24,1.2.3.4` | будь-які | дозволені адреси чи мережі; `""` — будь-які |
| `--allow-query` | ні | дозволити токен у адресі (`?token=`) — для браузера й простих прошивок. На VPN-вході не діє |

## Приклади

```bash
# телефон: лише свої громади, з будь-якої мережі
sudo alertcast token add --name "Телефон" --regions 1234,5678 --rpm 30 --streams 1

# домашній ESP8266 у VPN: лише з адреси тунелю, лише опитування
sudo alertcast token add --name "ESP8266 кухня" --regions 32 --ip 10.77.0.12 --streams 0 --rpm 10

# гостьовий доступ на тиждень
sudo alertcast token add --name "Гість" --regions 4 --expires 7d --rpm 20

# бот: усі регіони, кілька потоків
sudo alertcast token add --name "Telegram-бот" --rpm 120 --streams 4

# переїхали: змінити регіони, решта лишається
sudo alertcast token edit 0d5d4366 --regions 33
```

Те саме — в адмінці, розділ «Токени»: створення з QR-кодом (адреса сервера + токен),
редагування, rotate, відкликання, відкриті потоки й причини відмов ([admin.md](admin.md)).

## Тестова область

Щоб перевірити пристрій чи бота без справжньої тривоги, дайте токену тестову область і
вмикайте тривоги вручну — кнопками в адмінці (розділ «Тестова область») або з консолі:

```bash
sudo alertcast token edit 0d5d4366 --regions 32,990000    # додати тестову область до регіонів
sudo alertcast testregion set 990100 red                  # «ракети» в Тестовому районі 1
sudo alertcast testregion set 990100 yellow --type AIR    # змінити рівень
sudo alertcast testregion set 990100 none                 # відбій
sudo alertcast testregion clear                           # зняти все
```

Регіони: `990000` Тестова область → `990100` Тестовий район 1 (громади `990101`, `990102`)
і `990200` Тестовий район 2. Ієрархія та сама, що для справжніх регіонів. Тестову область
бачать лише токени, яким її дозволено явно; у сумісному v3 і на публічній сторінці її немає;
кожен її стан має `"test": true`. Тривога без змін довше за годину знімається сама.
