# Адмінка

Вебпанель для одного адміністратора: токени, моніторинг розсилання, тестова область, журнал.

## Доступ

- Служба слухає `ADMIN_LISTEN` (типово `127.0.0.1:8793`, лише loopback — інше не запуститься).
- Назовні адмінку відкриває **окремий VPN-сайт** панелі (Caddy) → `127.0.0.1:8793`. Публічного
  сайту для адмінки не робіть: вхід через VPN — перший рубіж, пароль і 2FA — другий.
- Сайт має бути на HTTPS: cookie сесії `__Host-ac_admin` має прапорець `Secure`.

## Перший вхід

```sh
sudo alertcast admin setup
```

Команда питає пароль (від 12 символів, двічі, без відлуння), показує QR для застосунку 2FA
(Google Authenticator, Aegis, 1Password…) і ключ для ручного введення, просить один код для
перевірки й лише тоді зберігає. Повторний `setup` (загубили телефон або пароль) замінює
обидва й завершує всі сесії.

```sh
sudo alertcast admin status   # чи налаштовано
sudo alertcast admin logout   # завершити всі сесії адміна
```

## Захист входу

- Пароль — PBKDF2-SHA256, 600 000 ітерацій, сіль; перевірки йдуть по одній (не DoS).
- 2FA — TOTP (RFC 6238, 30 с, ±1 крок). Кожен код приймається **один раз**, і після перезапуску теж.
- Після невдачі — пауза 1, 2, 4, 8 с; 5 невдач з адреси за 15 хв — блок адреси на 15 хв;
  20 невдач загалом за 15 хв — вхід закрито для всіх на 5 хв. Усе — у журналі.
- Сесія: 30 хв простою, максимум 12 год, до 5 одночасно; живе в пам'яті (перезапуск — вхід знову).
- Зміни (POST/PATCH/DELETE): потрібні cookie, заголовок `X-CSRF` сесії, `Origin` цього ж сайту
  й `Content-Type: application/json`; невідомі поля JSON відхиляються, тіло ≤ 64 КБ.
- Сторінки — статичні файли під жорстким CSP (`script-src 'self'`, без inline-скриптів і стилів,
  `frame-ancestors 'none'`); дані вставляються лише як текст.

## Що є в адмінці

- **Моніторинг** — стан alertcast і alertd, свіжість даних, потоки; графіки за 24 год:
  затримка (повний шлях ukrainealarm → пристрій, webhook, наша доставка), потоки, запити (успішні,
  401/403, 429); журнал і заблоковані адреси (можна розблокувати). Оновлюється наживо.
- **Токени** — пошук, фільтри, створення (секрет і QR показуються один раз), редагування,
  rotate, відкликання, відкриті потоки (можна закрити), запити й причини відмов за 24 год.
  QR містить `{"url": PUBLIC_URL, "token": …}`.
- **Тестова область** — кнопки рівнів для кожного тестового регіону, хто з токенів її бачить.
- **Журнал** — входи, зміни токенів, блокування, свіжість даних, тестова область, старт і
  зупинка служби; зберігається 30 днів.

Похвилинні метрики (24 год) і журнал зберігаються в тій самій БД, що й токени.
