# Розробка

Go 1.26+. Одна пряма залежність — [go-sqlite3](https://github.com/ncruces/go-sqlite3) (чистий
Go, без cgo і JIT) для БД. Сторінки (адмінка, `/docs`, головна) — вбудовані у бінарник
статичні файли з `www/`, без збірки фронтенду й бібліотек.

## Збірка

```bash
go build -o alertcast .
scripts/package.sh 1.0.0          # dist/alertcast-1.0.0.tar.gz + SHA256SUMS
```

## Тести

Тести не потребують справжнього alertd: вбудований підставний alertd відтворює `/regions`,
`/state`, `/health` і потік `/events` з обривами, зміною бази й `resync`.

```bash
go test ./...                                                        # усе, крім бінарника
go build -o /tmp/alertcast . && ALERTCAST_BIN=/tmp/alertcast go test ./...   # + наскрізні
go test -race ./...                                                  # гонки
SOAK=1 go test -run TestSoakStreams -v .                             # 1000 потоків
go test -run '^$' -fuzz FuzzAPIRequest -fuzztime 60s .               # фазинг запитів
go test -run '^$' -fuzz FuzzAlertdStream -fuzztime 60s .             # фазинг потоку від alertd
```

Адмінку й `/docs` з даними можна подивитися локально без alertd:

```bash
mkdir -p /tmp/demo && DEMO_DIR=/tmp/demo go test -run TestDemoServer -timeout 0 .
# адмінка: http://localhost:<порт з /tmp/demo/addr>, пароль pass-pass-pass,
#          секрет 2FA — /tmp/demo/secret; публічний сайт і /docs — адреса з /tmp/demo/public
```

| Група | Що перевіряє |
|---|---|
| Модель | ієрархія на всіх рівнях; 400 випадкових станів проти незалежної еталонної реалізації; цикли й сироти в дереві; сумісність з v3 |
| Джерело | відновлення після обриву без втрат; зміна бази alertd (зокрема коли нові номери вже більші за старі); `resync`; сторожовий таймер; `stale` |
| Безпека | однакова 401; ліміти; блокування підбору; справжня адреса клієнта; обмеження регіонів; токен у адресі |
| Потоки | знімок і зміни; без шуму від чужих областей; ліміти; відкликання, зміна й завершення терміну посеред потоку; 100 потоків сходяться до фінального стану |
| Керування | сокет, перевірка полів, збереження, сирий токен ніколи не в БД |
| Адмінка | пароль і TOTP (вектори RFC 6238), повтор коду, паузи й блокування входу, сесії, CSRF, `Origin`, API токенів і тестової області, порожні дані, журнал і метрики |
| Сторінки | головна (без тестової області, `ETag`), `/docs`; QR-коди версій 1–10 (розпізнавання OpenCV: `scripts/qrcheck.py`) |
| Наскрізні | бінарник: запуск, токени через CLI, адмінка в `check`, перезапуск зі збереженням, коректна зупинка |
| Навантаження | 1000 потоків: доставка ~15 мс (медіана), ~35 мс (p99) |

## Реліз

1. Оновити `CHANGELOG.md`.
2. **Actions → release → Run workflow** з версією `X.Y.Z` (або `git tag vX.Y.Z && git push --tags`).

## Структура

| Файл | Що |
|---|---|
| `main.go` | налаштування, команди, запуск, `check` |
| `source.go` | зв'язок з alertd |
| `model.go` | дерево регіонів, сирий стан, обчислення стану з ієрархією |
| `compat.go` | сумісність з ukrainealarm v3 |
| `hub.go` | потоки: індекс за областями, ліміти, прапорець змін |
| `api.go` | HTTP: автентифікація, ліміти, API, адреса клієнта, локальний API |
| `tokens.go` | токени (SQLite), ліміти запитів, захист від підбору |
| `admin.go` | сокет керування й команди `token`, `testregion` |
| `admincli.go` | команди `admin setup/status/logout` |
| `adminauth.go` | пароль, TOTP, сесії й захист входу адмінки |
| `adminweb.go`, `www/admin/` | вебадмінка: API й сторінки |
| `metrics.go`, `journal.go` | похвилинні метрики за 24 год і журнал подій (у БД) |
| `testregion.go` | тестова область |
| `publicpage.go`, `www/index.tmpl` | головна сторінка — таблиця тривог |
| `docs.go`, `www/docs/` | опис API `/docs` |
| `qr.go` | генератор QR-кодів (термінал і SVG) |
| `session.go` | сесії браузера (cookie) |
| `verify.go` | звірка з живим ukrainealarm |
| `sdnotify.go` | готовність і сторожовий таймер systemd |
| `pages.go`, `www/page.tmpl` | сторінки помилок і `/s` для моніторингу |
| `deploy/` | unit systemd, скрипти встановлення й оновлення, шаблон налаштувань |
